# 2026-10-10 · 解读准确性优化：VLM 四环节框架落地

> 状态：待启动
> 来源：2026-10-10 多模态调研对话。概念与框架详见 `knowledge/ai/收件箱/2026-10-10-VLM解读准确性-概念与优化框架.md`
> 背景：调研确认曼陀罗项目的核心瓶颈不是成本/延迟，而是「看画看得准不准」——VLM 视觉幻觉（语言先验压倒视觉证据，背曼陀罗话术而非看具体画作）是最大风险。竞品青柠心栈实测报告无解读内容，疑似此路未走通，可靠性工程即差异化点。

## 输入

- 现有解读智能体 pipeline（docs/tasks 既有 v2 链路）
- `knowledge/ai/收件箱/2026-10-10-VLM解读准确性-概念与优化框架.md`（四环节框架，明镜项目共用）
- 疗愈知识库曼陀罗颜色/构图/象征体系（knowledge/healing/术/流派/曼陀罗/）

## 输出

1. 模型盲测结果：10–20 幅真实曼陀罗 × 主流 VLM 的「描述画面」人工评分对比 → 选型结论
2. 对抗测试记录：「违反常识」曼陀罗样本，检验模型是否套模板
3. 两阶段 pipeline 改造：阶段1 裸看只描述画面事实（不注入解读知识）；阶段2 注入知识库做解读；每条解读带画面证据引用
4. JSON Schema 校验层：证据缺失字段打回重做
5. 评测集 v1：20–50 幅 + 本人标准解读 + LLM-as-a-Judge 双维度评分脚本（画面描述忠实度 / 解读专业度）
6. 带文字曼陀罗处理（异常路径，本人实测发现）：阶段1 拆两路——1a 只看绘画区域描述画面，1b 原文转录图中文字不解读；阶段2 画面描述为主要依据、文字标注为「用户自述」与画面对照（一致→印证；冲突→潜在解读点）。防止文字悄悄渗入解读造成"偷看答案的准"。详见笔记第五节

## 边界

- 不做模型微调（垂直标注数据稀缺 + 迭代快，prompt + 知识库注入 ROI 更高）
- 不优化成本/延迟（当前规模非瓶颈）
- 知识库内容本身的修订走 knowledge/healing 护栏流程，不在本任务内

## 验收方式

- 评测集跑通，基线 vs 改造后双维度分数可对比
- 对抗测试样本不再被套模板话术
- 报告中每条解读可追溯至画面具体位置
- 评测集中包含带文字曼陀罗样本：文字被正确转录且标注为「用户自述」，不混入画面解读依据

## 建议顺序

评测集先行（罗盘先造），再做盲测选型，最后 pipeline 改造——避免凭感觉优化。
